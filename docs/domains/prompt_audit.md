# 提示词审计与会话证据

本文拥有独立提示词检测引擎、增量审核、深审、检测节点及会话证据的契约。实现位于 `internal/securityaudit`，管理界面为 `/admin/prompt-audit`。既有内容审核、团队账务、历史归属和创作台无留存规则继续由各自领域拥有。

## 模式与作用范围

全局风控开关与提示词审计开关同时开启后才执行检测。默认关闭，不自动配置或调用外部检测节点。支持全部分组或指定分组；不在范围内的请求不建立提示词审计事件。

| 模式 | 行为 |
| --- | --- |
| 关闭 | 保留现有内容审核，提示词引擎不运行 |
| 异步审核 | 主请求不等待 Guard 结果，任务持久化并由 worker 检测 |
| 同步阻断 | 上游发送内容前执行检测，明确 Block 返回 403；允许后按深审规则异步补查 |
| 异步深审 | 使用独立的深审模块选择，补充检测系统指令、助手、推理、工具等内容 |

管理端可选择最多 100 名阻断豁免用户：冻结本次请求的豁免标记，完整异步审计并保留结果，不以之后的配置覆盖历史事件。豁免只作用于提示词引擎，不放宽 TokenRouter 原有关键词、hash 或外部内容审核规则。团队请求以实际行为用户作为风险主体，账务用户与团队 ID 单独传递，避免误归因给付款人。

## 提取与入口边界

提取使用已有 `internal/auditcontent` 规范文档，不把客户端可控角色或工具结果当作可信安全证明。同步和深审可分别选择系统指令、助手消息、推理、提示变量、工具定义、调用参数和结果。无法提取或存在不完整兄弟字段的请求不能伪造安全结论；同步阻断模式保留明确错误。诊断只记录有界结构、字段种类及摘要，不记录节点实际值。

Responses、Chat Completions、Messages、Gemini 复用当前 handler 的前置审核入口，Responses WS 首轮及后续每轮执行；Qoder 分派也接入同一边界。嵌入文本、Alpha Search、图片/视频提示词、TTS 文本、搜索请求与批量图片提示词均在相关内容发往上游前检测。批量图片在创建任务和冻结额度前合并审核全部条目文本。

Live/Grok 实时连接的客户端文本事件在转发前检测，Live 侧带先审核原始帧再执行模型转换。语音转写、音频二进制、图片本体和 WebRTC 媒体不被宣称为通过文本检测；已有媒体审核能力继续独立生效。计数入口沿用当前已存在的审核调用点。取消、查询任务等不含提示词的控制操作不创建检测任务。

创作台直接使用其原有 `NoMediaRetention` 内容审核入口，不接入会话正文留存；不能把创作台输入复制进提示词审计表。协议改动必须同时验证原始输入、当前轮边界、HTTP/WS 和相关副作用顺序。

## 检测节点与失败语义

节点使用 OpenAI-compatible 接口，可配置名称、模型、密钥、超时、输入分片上限和启用状态；按优先级故障转移。配置采用版本比较更新，密钥加密保存，API 只返回是否配置，空值保留旧密钥，清空需显式操作。保存配置要求稳定加密密钥；通过 Redis 通知及周期刷新同步实例。

检测输入出站前执行敏感信息脱敏，限制 URL/重定向、并发、输入、超时与重试，节点错误不透传原始请求或密钥。类别启用列表在服务端过滤，未启用类别不能影响最终判定。

明确安全结果分为 Pass、Flag、Critical；Critical 对应阻断，Flag 保留风险但允许继续。节点全部不可用、超时等最终 `prompt_guard_unavailable` 结果按用户选择放行，同时记录失败事件和运行指标，不能冒充 Pass。内容提取失败、无可信配置、深审恢复状态异常仍保留各自错误，不通过放行节点故障来绕过这些边界。异步队列有容量、任务租约与重试上限，最终失败生成可查询事件。

## 免重复审核与深审状态

Allow 回执绑定用户、策略版本、来源和规范化片段内容，默认 TTL 一小时，可配置 60–86400 秒。只有可信成功检测可生成回执，异步入队、节点故障放行或豁免请求不能凭空生成安全凭据；历史片段缺少有效回执时需再次审核。

命中阻断后按用户保存深审要求，不以 API Key 或客户端 session 改变逃避。后续范围内请求使用完整深审模块且绕过回执缓存。Redis claim 和 finding token 保护并发确认，旧请求不能清除新风险状态。离开分组范围或进入豁免不会删除已有风险，重新进入后继续生效。

## 会话证据与留存

迁移 `268_prompt_audit.sql` 创建任务、事件、会话与内容记录表，编号遵循当前工程，不使用旧工程编号。事件表保存脱敏摘要与关联信息；完整上下文压缩后使用应用密钥加密，带完整性校验。沿用旧工程，选中送审文本保存在独立聊天记录的 `full_prompt` 中，不能把这一列误称为加密字段；数据库备份按敏感数据保护。普通日志和事件列表均不返回正文。

会话标识来自显式 session header、conversation_id 或 thread_id，按用户、协议和来源哈希；不使用可跨会话共享的 prompt_cache_key。没有显式标识时使用请求级回退，界面显示来源。相同会话相同内容可复用，内容变化产生新版本，不能用当前内容覆盖旧事件证据。

普通 Pass 内容从最近出现起保留七天；管理员选定用户的 Pass 证据及风险证据长期保留。过期后事件元数据仍可查询，详情和下载立即拒绝过期内容，不必等待周期清理；删除事件后回收孤立内容。内置逻辑备份始终排除聊天正文表和旧上下文兼容表，保留可恢复事件元数据；完整运维灾备需单独按受限权限管理。

管理界面提供三个标签：审计事件、会话证据、配置。会话证据可按用户分页，显示事件/风险/可用证据数量，进入后查看关联事件并打开证据详情；“管理该会话事件”进入带精确会话筛选的事件列表，可使用原有批量删除和预览确认流程；完整上下文下载按钮在详情顶部。不可用状态区分为未留存或已过期，不显示无效下载入口。会话列表仅返回元数据，事件详情和下载受管理端鉴权、操作审计及 `no-store` 约束。

## 运行与验证

Wire 装配 `PromptService`，主入口在监听前加载配置并启动 worker，Cleanup 在数据库和 Redis 关闭前停止任务。运行页展示配置版本、队列、worker、节点探测、提取失败、回执、深审和 Guard 结果计数。功能关闭不影响原有网关路径。

验证覆盖完整引擎单元测试、真实 PostgreSQL/Redis 迁移/配置 CAS/任务/留存/删除/会话隔离、管理员权限、HTTP/WS 前置阻断及前端页面交互。现有 CI 的测试任务提供隔离 PostgreSQL/Redis 服务运行本模块存储集成测试，根 Makefile 的前端关键测试集包含提示词审计目录。会话证据测试必须覆盖从会话到事件详情与下载的可达性，并验证到期但尚未清理时不能继续读取。
